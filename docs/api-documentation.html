Internal Transfers API

Robust HTTP API for internal financial transfers with PostgreSQL backend

🏦 Account Management

Create accounts with initial balances using integer account IDs. Supports high-precision decimal amounts with up to 5 decimal places.

💰 Balance Queries

Query account balances with precise decimal formatting. All monetary values returned as strings to preserve precision.

🔄 Financial Transactions

Process transfers between accounts with atomic operations. All transactions either succeed completely or fail completely.

📊 Transaction Logging

Complete audit trail with transaction history. Every transfer creates a permanent record for compliance and tracking.

🔒 Data Integrity

Atomic transactions with automatic rollback on failure. Database-level consistency guarantees for all operations.

🎯 Decimal Precision

High-precision financial calculations using DECIMAL(15,5) format. No floating-point precision loss for monetary operations.

Business Rules & Validation

Account Management

  • Account IDs must be positive integers
  • Account IDs must be unique across the system
  • Initial account balances cannot be negative
  • Accounts cannot be deleted once created

Transaction Processing

  • Transaction amounts must be positive
  • Source and destination accounts must be different
  • Source account must have sufficient balance
  • All operations are atomic (succeed completely or fail)

Data Precision

  • All amounts use decimal arithmetic (no floating-point)
  • Supports up to 5 decimal places
  • Input/output as strings to preserve precision
  • Database stores DECIMAL(15,5) format

Quick Start Examples

1. Create Account

Create a new account with initial balance:

POST /accounts

{"account_id": 123, "initial_balance": "1000.50"}

2. Check Balance

Query current account balance:

GET /accounts/123

Returns: {"account_id": 123, "balance": "1000.50"}

3. Transfer Money

Process a financial transfer:

POST /transactions

{"source_account_id": 123, "destination_account_id": 456, "amount": "150.50"}

4. Health Check

Verify service status:

GET /health

Returns: "OK" (200 status)
